# Design decisions - Axell Master

Each decision gives the reason and how it is verified. The DSP lives in JUCE-free headers
(`Source/Engine.h` and the shared Axell core, `axell-core/include/axell/dsp`) so the test suite
measures exactly the code that ships.

## M1 - Signal path: gain -> oversampled clipper -> true-peak limiter -> dither
The world's best mastering limiters reach loudness in two stages: something fast and memoryless
shaves the shortest peaks (snare and kick transients last well under a millisecond) and a
look-ahead limiter handles the rest. Clipping a few tenths of a millisecond is inaudible where a
limiter doing the same work would have to pump. CLIP sets how much of the peak reduction is clipping:
the clipper threshold runs from 6 dB above the ceiling (0 %, nearly idle) down to the ceiling
(100 %). The limiter always follows, so the ceiling never depends on the clipper.
*Verified:* DSP suite §2 (every style x clip 0/50/100 % x link 0/100 %).

## M2 - Band-limited down path: the true-peak ceiling holds for any input
The oversampled section ends in a steep linear-phase decimator (flat to 0.455 fs, >= 120 dB down from
0.48 fs) at every sample rate; at 1x the same band limit is a linear-phase low-pass at the base rate. Everything that reaches the limiter then lies in the band where its
8-phase true-peak detector (128 taps, exact to 0.48 fs) is exact. Without it, harmonics generated by the
clipper near Nyquist could form inter-sample peaks the detector under-reads. Found by the independent audit:
before the 1x path had its own low-pass, a full-band mix clipped at 1x reached -0.37 dBTP against a -1 dBTP
ceiling. Cost: latency (373 samples = 7.8 ms at 48 kHz with the 16x default, 318 at 1x; compensated by the host).
*Verified:* §2 measures the output with an independent long-sinc reconstruction (16 points per sample,
+-512 taps), not with the plugin's own detector, including full-band input clipped at 1x..16x; the audit
repeats it through a VST3 host with an FFT reconstruction.

## M3 - Clipper knee: never a mathematically hard clip; 16x oversampling by default
A true hard clip has an infinite spectrum; at 4x the 39th harmonic of a 5 kHz tone folds back to 3 kHz.
SHAPE runs the quadratic knee from 50 % of the threshold (soft) to 15 % (hard): sonically still hard,
but the harmonics decay fast enough to stay below the oversampling's reach. Measured worst alias,
5 kHz hard-clipped 6 dB (worst of 44.1 / 48 / 96 kHz): 4x -76 dBc, 8x -94 dBc, 16x -106 dBc (an ideal 4x
model of the same curve gives the same; the filters, 120 dB stopbands, are never the floor). 8x and 16x use
short halfband stages with a 0.5 fs pass edge: they only reject the images of a band-limited signal (up)
and what would fold below 0.48 fs (down), so 16x costs 4 samples of latency and ~1 % CPU over 4x - which is
why 16x is the default: no reason to accept -76 dBc.
*Verified:* §3.

## M4 - Limiter: per-channel envelopes, stereo link blended in dB
Each channel computes its required attenuation (running maximum over the look-ahead, then release,
then three cascaded moving averages for a smooth, overshoot-free attack). LINK blends each channel's
gain towards the common (largest) one in dB. At 100 % the stereo image cannot move; lower values give
more loudness on wide mixes. The ceiling holds at any link because each channel's own requirement is
always met.
*Verified:* axell-core tests (4 styles x link 0/100) and §2.

## M5 - Release styles: program-dependent release
A single release time is either too fast for dense passages (pumping, bass distortion) or too slow for
isolated peaks (audible holes). Each style has a fast and a slow release, blended by a memory of how
long the limiter has been working: a lone snare recovers in ~100 ms, two seconds of dense limiting
recover ~6x slower. TRANSPARENT (default), PUNCHY (faster after transients), LOUD (densest), SAFE
(slowest, longest hold).

**Bass-aware hold.** A look-ahead limiter releases as soon as a waveform peak has passed; under steady
limiting of a 50 Hz bass the gain then recovers a little between the peaks every 10 ms - a 100 Hz gain
ripple, which is distortion. A second running maximum spans the look-ahead plus 15 ms (25 ms for Safe:
half a period of 33 Hz / 20 Hz) and is blended in by the same memory that slows the release: lone
transients (memory empty) recover exactly as before, sustained limiting holds the gain through the bass
cycle. The held attenuation is never below the required one, so the ceiling is untouched. Measured, 50 Hz
at ~6 dB of limiting: Transparent -54 -> -139 dB THD+N, Safe -60 -> -139 dB, Punchy -48 -> -83 dB, Loud
-39 -> -57 dB; recovery after a lone peak unchanged (110 ms); loudness cost 0.08 dB.
*Verified:* axell-core recovery test, §4 (all rates), audit 4b (40 Hz through a VST3 host).

## M6 - Latency changes wait for the host (latency handshake)
Oversampling and look-ahead change the latency. A new latency only plays after the host was told
and had time to re-align (the audio stays muted while waiting, then fades in). No DAW ever plays a
block whose delay disagrees with what it compensates.
*Verified:* §9 and the plugin suite §3 (5 switches, every sample stays under the ceiling, the reported
latency matches the engine each time).

## M7 - COMPARE is level-matched by loudness, not by peak
COMPARE plays the unprocessed input at the master's loudness (K-weighted mean square over 0.4 s,
gain smoothed over 0.25 s, the same delay as the master). Louder always sounds better; a peak-matched
compare would make the master sound up to 10 dB louder than the input and hide what the processing
does.
*Verified:* §6 (difference < 1 dB at 8 dB of loudness gain).

## M8 - LEARN measures audio, not the clock
LEARN resets the integrated loudness of the output and waits for at least 3 s of measured audio (works
in an offline render too), then moves GAIN by (target - integrated). Limiting is non-linear, so a second
pass lands within a few tenths of an LU.
*Verified:* plugin suite §7 (-27.2 LUFS mix -> -13.96 LUFS after two passes, true peak still -1.05 dBTP).

## M9 - Presets never change GAIN
How hard to drive depends on the mix, not on the genre: a preset that changed GAIN would jump the
master by up to 10 dB. Presets set clipper, limiter, target and ceiling; GAIN stays where it was.
*Verified:* plugin suite §4.

## M10 - Dither only on request, deterministic, psychoacoustically shaped
Off by default (the master usually goes to a 24/32-bit float file). 24-bit and 16-bit TPDF, or 16-bit
shaped with the 9th-order F-weighted minimally audible error-feedback filter published by R. A. Wannamaker
("Psychoacoustically Optimal Noise Shaping", J. Audio Eng. Soc. 40(7/8), 1992): noise transfer -25 dB at
3 kHz, the noise moved above 15 kHz, minimum phase (mean log gain 0 dB, as Gerzon-Craven requires). The
stored error is bounded so a full-scale clamp can never destabilise the loop. The generators are
deterministic per channel: repeatable renders, uncorrelated left and right.
*Verified:* axell-core (vs TPDF: -22 dB at 2-5 kHz, -12 dB below 1.5 kHz, peak error 16 LSB = stable), §7
(16-bit grid), §8 (bit-identical across block sizes), audit 6.

## M11 - Loudness metering to the standard
ITU-R BS.1770-4 / EBU R128: K-weighting, 400 ms momentary, 3 s short-term, gated integrated (-70 LUFS
absolute, -10 LU relative), loudness range per EBU Tech 3342, true peak per BS.1770 Annex 2 with 8x
(twice the standard's minimum 4x) polyphase oversampling.
*Verified:* axell-core: EBU Tech 3341 cases 1-5 and Tech 3342 cases 1-4 at 44.1, 48 and 96 kHz.

## M12 - True-peak margin 0.02 dB
The limiter aims 0.02 dB below the ceiling: more than 6x the detector's worst interpolation error up to
0.48 fs (0.003 dB; D21 of Axell Duo Compressor), and M2 guarantees the input never has content above
0.48 fs. 0.05 dB (the Duo/Penta value) would give away loudness for no safety gain.
*Verified:* the worst true peak over every reference-checked case in §2 is -1.018 dBTP for a -1 dBTP ceiling.

## M13 - 2.0: the streaming codec check (why)
A true-peak ceiling protects the master file. Streaming services do not play that file: they re-encode it with a lossy
codec, which keeps the spectrum, not the waveform, so the decoded peaks of a loud master land higher than the
master's. `research/real_masters.py` masters three real rap mixes with 1.0 at -9 LUFS (Boom Bap Punch / Loud Rap /
Club presets, GAIN found for the target) and decodes them with ffmpeg's encoders:
- **At the -1 dBTP ceiling:** decoded true peaks up to +0.6 dBTP (native AAC 256k) and +1.14 dBTP (Vorbis 160k,
  Spotify's "high" quality), with up to 68 clipped samples per song. Opus 160k (YouTube) stayed at -0.1 to -0.3.
- **At Club's -0.5 dBTP:** Opus clipped too (12-30 samples). At -14 LUFS nothing clipped: the mixes needed no limiting.
So "-1 dBTP" is not enough for a loud rap master, and 1.0 could not show it.

## M14 - The check measures the real codecs, at several framings
- **Real codecs:** the master is encoded and decoded with the reference libraries:
  - Opus 1.5.2 at 160 kbps (complexity 10, music);
  - libvorbis 1.3.7 at 160 kbps (average bitrate without slow rate management, as ffmpeg's `-b:a`).
  Both are BSD-licensed, so they ship in the AGPLv3 plugin. AAC cannot be embedded: the reference-quality encoder
  (FDK) has a licence incompatible with the AGPL.
- **How it is measured:** the decoded signal goes through the core's 8x true-peak meter, plus a count of samples
  beyond full scale.
- **Validated:** the in-plugin Opus matched ffmpeg's within 0.16 dB on three masters. The in-plugin Vorbis matched
  ffmpeg's Vorbis within 0.1 dB once both started at the same sample.
- **Framing decides the peaks.** The same master shifted by a few samples moved the decoded true peak:
  - Vorbis by up to 0.9 dB (periodic in 128-sample steps, the short-block hop, but erratic within a period);
  - Opus by 0.4-0.7 dB;
  - native AAC by 1.0 dB.
  The service's framing is unknown, so each codec runs at four start offsets (0, 211, 523, 857 samples), and the
  worst result counts.
- **Threading:** the codecs run on their own worker thread, about 15 % of one core for all eight streams. The audio
  thread only copies the output into a lock-free ring (no allocation: tested). A render far faster than real time
  that outruns the worker is flagged INCOMPLETE, never blocked.
- **Sample rates:**
  - Opus needs 48 kHz: 44.1 kHz is resampled (De-Reverb's polyphase resampler).
  - At 88.2 / 96 kHz both codecs run on the 48 kHz copy (no service streams at 96 kHz, and libvorbis has no 160 kbps
    mode there).
- **What is measured:** the master as exported. The level-matched COMPARE signal and host bypass are not measured.
  Any change to the processing restarts the measurement.
*Verified:* DSP suite (decoded level of sines at 4 rates; clip counting; SAFE arithmetic; reset; silence; overflow
flag; worker thread; push() allocation-free), plugin suite (SAFE, COMPARE not measured, off = nothing measured, 1.0
projects), audit 10 (on vs off bit-identical audio).

## M15 - SAFE: lower the ceiling until the codecs decode below full scale
- **What it does:** SAFE lowers the ceiling, in its 0.1 dB steps, by however far the worse codec's decoded true peak
  is above -0.3 dBTP, and restarts the measurement.
- **Why it can take more than one press:** a lower ceiling means denser limiting, and denser material overshoots more.
  The decoded peak falls by only 30-100 % of the ceiling change, so after playing again SAFE may offer another,
  smaller step.
- **Calibration** (`research/codec_safe_study.py`, results in `codec_safe_study.txt`): 9 masters (3 mixes x 3 loud
  presets at -9 LUFS). SAFE was repeated as a user would, and each result went through 6 encoders at 6 start offsets
  each, offsets different from the check's own.
  - Target -0.3 dBTP: 1-3 presses, 0 clipped samples with Opus 160, Vorbis 160 and 320, FDK AAC 256 and MP3 320.
    Worst decoded true peak -0.08 dBTP (Vorbis 160).
  - The cost: a -9 LUFS master ends at -9.6 to -10.3 LUFS (final ceilings -1.9 to -2.8 dBTP).
  - A single SAFE press left up to 4 clipped samples in Vorbis.
  - Target -0.5 gave the same safety with more loudness given up.
- **ffmpeg's native AAC encoder is excluded from the acceptance.** It produces spikes unrelated to the master: up to
  +4.9 dBTP while every other codec decoded at -2 dBTP, and it got worse when the ceiling went down. No ceiling can
  protect against an encoder defect. FDK AAC, the reference-quality AAC encoder, stayed at or below -1.35 dBTP
  everywhere.
*Verified:* the study above; plugin suite (a +16 dB master into -0.1 dBTP: SAFE proposes exactly the step to the
target in 0.1 dB steps, and the ceiling moves).

## M16 - 2.0 presets
Club / CD: ceiling -0.5 -> -1.0 dBTP. At -9 LUFS, -0.5 clipped after Opus and Vorbis on every test master. The other
loud presets keep -1 dBTP: the codec check and SAFE take each song as far as it needs.

## M17 - 2.0: 20 more presets, each checked on real material
Asked for: 5 for the artist's own work (underground boom bap, rapped vocals recorded in a booth, streaming releases,
beat production) and 15 general ones for masters, vocal buses and beat / drum buses. In the menu they are grouped:
MASTER, YOUR STUDIO (BOOM BAP), VOCAL BUS, BEAT / DRUM BUS. 1.0's eight keep program numbers 0-7.

**How they were checked.** `research/presets_study.py` runs every new preset through the shipping engine
(`tools/MasterRender`) on fitting material:
- **Masters:** the artist's three mixes, GAIN found for the preset's target as LEARN does. Measured: loudness, true
  peak and the decoded codec peaks.
- **Vocal-bus presets:** the artist's dry and processed vocals, driven until the loudest peaks lose the amount the
  description promises.
- **Beat / drum-bus presets:** the beat-only first 21 s of two bounces, driven the same way.
- **For all:** the 10-20 kHz energy added re a plain gain change (the grit clipping adds) and the crest factor.

**What it showed** (all of it in `research/presets_study.json`):
- **The -14 LUFS masters** have nothing to do on these mixes: they already sit at -14 LUFS with peaks at -1.7 to
  -2.5 dBTP. The artist's mixes need no limiting for streaming.
- **The loud boom bap preset changed:** at -2 dBTP, 2 of 3 masters still decoded at +0.5 dBTP with clipped samples.
  A search over ceiling and clipping (`preset_loud_boombap_search.txt`) chose clip 45 % with a -3 dBTP ceiling.
  - Result: 0 clipped samples on all three, worst -0.26 dBTP decoded, without SAFE.
  - LEARN lands at -9.3 LUFS there: the limiter is at its density limit.
- **EDM / Electronic Loud (-1 dBTP at -9 LUFS)** decodes at up to +0.75 dBTP (16-21 clipped samples). Its description
  says SAFE is needed at that loudness.
- **The vocal presets** take exactly their 3-6 dB of peak reduction and add at most +0.4 dB of 10-20 kHz energy;
  Sung Vocal and Vocal Peak Catcher add +0.1 or less.
- **The beat presets:**
  - 808 / Sub Control adds none (-0.15 dB; the Safe style's bass-aware hold, no clipper).
  - Sample-Based Beat Glue adds +0.1 dB, Boom Bap Drum Bus Knock +0.8, Drum Bus Punch +1.1.
  - Trap Beat Hard Clip adds +2.4 dB: the grit it is named for.
- **Podcast / Spoken Word** reaches -16 LUFS with 1.7 dB of peak control. **Mix Bus Safety** touches only the overs.
*Verified also:* DSP suite (every preset: finite, sample peak below its ceiling, at three rates); plugin suite (28
presets, 1.0's eight first in order, every preset has a group, a description and a unique name; every program
applies its values and keeps GAIN).

## M18 - 3.0: VOICE HOLD for a vocal bus (from Axell Duo Compressor 3.0 and Axell Gate)
- **The problem.** On a vocal (bus) the drive lifts everything and the limiter pulls the words back down, so the room,
  breaths and bleed between phrases come up by the amount of limiting. On the artist's real take (gated), the vocal
  presets driven +12 / +18 dB lifted the pauses re the voice by +3.2 .. +13.9 dB.
- **The cluster's answer.** Axell Duo Compressor 3.0 solved it for compression with the suite's voice decision (Axell
  Gate 2.0's detector in axell-core, causal, 10 ms): in a pause the release stops and the gain glides (12.5 ms) to the
  voice's recent average (0.25 s). The same is now in the core's MasterLimiter (optional per-sample pause flags; the
  attack and the ceiling guarantee are untouched; without flags bit-identical - CoreTests). A pause counts only within
  10 s of a voice.
- **Measured** (the artist's take, `tools/MasterRender --voice-hold`, pauses re voice, off -> on; the voice's own
  reduction and level spread unchanged within 0.2 dB):

  | preset | +12 dB | +18 dB |
  |---|---|---|
  | Vocal Peak Catcher | +8.1 -> +2.7 dB | +13.9 -> +4.6 dB |
  | Sung Vocal (Smooth) | +3.2 -> 0.0 dB | +6.8 -> +0.7 dB |
  | Booth Rap Vocal Bus | +3.4 -> +1.7 dB | +6.1 -> +2.5 dB |
  | Vocal Upfront (Dense) | +3.7 -> +2.4 dB | +6.2 -> +3.1 dB |
  | Ad-libs / Background Vocals | +4.1 -> +2.7 dB | +7.0 -> +4.9 dB |

  What remains in the clipping presets is the clipper's own peak reduction (a static curve has no release to hold).
- **Off by default**, on for the vocal presets: the voice network takes drum hits for a voice (Duo D31), so on a mix
  or a beat it would hold the limiter in the wrong places.
- **Tried and not shipped: ESS GUARD** (`research/ess_guard_study.py`). Velvet's sibilance network eased the clipper on
  esses so the limiter would take those peaks. On the artist's mix at equal loudness: Boom Bap Loud -2.8 dB of
  "crunch" on the esses but +0.5 dB elsewhere (more drive needed); Loud Rap / Trap slightly worse on the esses; no
  effect where the clipper is light. No net gain.
